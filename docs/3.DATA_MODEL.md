# 3. DATA MODEL

> Verified against `crates/pallama-core/src/store.rs` (SCHEMA_VERSION = 4) in Pallama v0.6.1.

## Database type(s) and justification

**SQLite** (embedded via `rusqlite` 0.32, bundled feature — no external SQLite dependency), file `<data_dir>/pallama.db`.

Justification: single-writer local metadata workload (engine roster, model catalog, per-(model,engine) profiles, key usage counters, bench history). Zero-ops, ACID, no server process to clash with the local-only product model.

Connection pragmas (set at open): `journal_mode = WAL`, `synchronous = NORMAL`, `foreign_keys = ON`, `busy_timeout = 5000` (ms).

Migrations: driven by `PRAGMA user_version` against `SCHEMA_VERSION = 4`. Version 4 added column `engines.kind` (via `ALTER TABLE` for pre-existing databases; rows created before v4 default to `'llamacpp'`).

Snapshot: `snapshot_db_to` uses `VACUUM INTO` — transactionally consistent, fails if destination already exists.

## Tables

### `engines`

| Field | Type | Nullable | Default | Notes |
|---|---|---|---|---|
| `tag` | TEXT | no | — | PRIMARY KEY |
| `asset` | TEXT | no | — | download/build provenance |
| `sha256` | TEXT | no | — | integrity digest of the engine artifact |
| `installed_at` | INTEGER | no | — | unix timestamp |
| `active` | INTEGER | no | 0 | exactly one row should have 1 |
| `manifest` | TEXT | no | — | JSON manifest |
| `kind` | TEXT | no | `'llamacpp'` | v4 column; one of `llamacpp`, `mistralrs`, `sglang` |

Key operations (store.rs):
- `upsert_engine` — `ON CONFLICT(tag)` updates asset/sha/installed_at/manifest/kind but **never touches `active`**.
- `set_active_engine` — single transaction: exists-check → `UPDATE active=0` (all) → `UPDATE active=1 WHERE tag=?`. Unknown tag → `Err`, state untouched. Invariant: never leaves zero active engines (failure path rolls back).
- `active_engine()` — `WHERE active = 1`.
- `list_engines()` — `ORDER BY installed_at DESC, rowid DESC` (newest first).
- `delete_engine`.

Lane-relevant manifest keys (engines.manifest JSON): `source` (`"fork"` \| `"upstream"` — drives `lane_class()` routing preference and fork-tree provenance re-stamping for `--source-dir` builds), `repo`/`ref_pin` (immutable fork pin, full SHA verified after fetch), `architectures` (mined from the build's `llama-arch.cpp`; the routing advertiser set), `trust` (curated/user tier), and supersede state `superseded_by` + `superseded_at_epoch` (stamped only when mainstream covers **every** lane architecture; there is no supersede column). The shipped registry file `registry/capability-lanes.json` mirrors one row per curated lane: `id`, `repo`, `ref_sha`, `upstream_pr`, `architectures`, `backends`, `status`, `added_at`.

Pull never uses this resolver — in pull targets the colon is the `owner/repo:QUANT` separator.

## Entity relationships

```
engines 1 ──── * profiles * ──── 1 models        (profiles = join on (engine, model))
models 1 ──── * loras                            (loras.model_name -> models.name)
[[keys]].name ──── * key_usage(name, day)        (usage rows keyed by config-defined key name)
engines/models ──── * bench_history              (denormalized tag/model strings)
models.mmproj_path -> mmproj file on disk        (not an FK; path reference)
```

No SQL foreign keys are declared between these tables (foreign_keys pragma ON applies to any FKs; these tables rely on application-level integrity). **INFERRED**: relationships are enforced by store API usage, not DDL constraints.

## Indexes and constraints

- PRIMARY KEYs as listed (`engines.tag`, `models.name`, `profiles(model_name,engine_tag)`, `loras.id`, `key_usage(day,name)`, `bench_history.id`).
- `engines.active` has no unique partial index — the "exactly one active" rule is enforced transactionally by `set_active_engine`, not by DDL.
- Application-level constraints: models name may not contain `#`; engine `kind` restricted by `EngineKind::from_str` at the application layer (unknown kind → teaching error `unknown engine kind ... (supported: llamacpp, mistralrs, sglang)`).
- WAL checkpointing is SQLite-default.

## Business invariants that must always hold

1. **Exactly one active engine** (or the intended pre-existing state) after any `set_active_engine` call — the store never transitions to zero active engines, even on unknown-tag errors.
2. **`models.name` never contains `#`** — upsert rejects it; `#` is reserved for replica instance keys (`model#N`).
3. **`profiles` rows are unique per (model_name, engine_tag)** — upsert replaces atomically.
4. **Quantized-safetensors detection never trusts `models.quant`** — the signal is `QUANTIZED_SAFETENSORS_TOKENS = [awq, gptq, fp8]`: true iff the path is NOT `.gguf` AND any word-boundary token of name/repo/path (lowercased, split on non-alphanumeric) is one of those tokens. Known mislabels: AWQ pulls record quant `4BIT`, fp8-dynamic records `BF16`. Word-boundary matters: a name containing `hawk` stays clean. GGUF paths never match.
5. **`key_usage` rows are whole-day absolute snapshots** — writers must never increment; they compute the day total and write it in one transaction.
6. **`engines.kind` legacy default** — rows predating v4 read as `llamacpp` (serde default), so kind-sensitive logic must treat missing kind as llamacpp.
7. **Colon resolution only onto existing rows** — `resolve_model_name` never creates a mapping; a miss returns the input verbatim.
