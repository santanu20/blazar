# v0.6.1 — Full engine routing, format-audited lanes, hardened engine store

Pallama 0.6.1 turns three engines into one server: routing picks the right
engine per model automatically, every Hugging Face file type is audited
(pull + serve lanes, live-proven where the hardware allows), and the engine
store got root-cause fixes for silent-failure classes found by live
benchmarks.

## Highlights

- **Engine routing v1** — `[engine_routing] mode = "auto"` picks the serving
  engine per model at spawn time (GGUF → llama.cpp, safetensors → SGLang or
  mistral.rs by `policy = "latency" | "quality" | "throughput"`). Default
  stays `manual` (byte-identical to 0.6.0). Per-model pin wins:
  `[model_overrides."name"] engine = "tag-or-kind"`. `pallama list`,
  `/v1/models` and `/api/tags` all show the routed engine per model — one
  shared resolver, they cannot disagree.
- **Policy is evidence-backed** (quiet-box matrix, RTX 4070 Laptop):
  quality/throughput → sglang (0.612 quality, 749.8 tok/s conc4); latency →
  mistral.rs (26 ms TTFT, 8 s cold); GGUF → llamacpp on every policy
  (quant-matched verdict: mistral.rs GGUF 0.462 vs llama.cpp 0.500/0.526 on
  the same Q4_K_M model).
- **HF format audit** — `docs/hf-format-coverage.md` maps every file type to
  its pull + serve lane with evidence tags. Newly live-proven on 0.6.1:
  AWQ (marlin, ~1.7× BF16 decode same-window), GPTQ-Int4 (329-358 tok/s),
  FP8-dynamic (~260-275 tok/s). Vanilla-AWQ JIT and flashinfer are blocked
  by nvcc ≤ 12.0 (documented ceilings, not silent failures).
- **Tuning surface** — ~95 first-class knobs across engines (25 sglang + 21
  mistral.rs + 6 llama-server + predecessors), LoRA adapter lanes, dotted
  config edits (`pallama config set sglang.grammar_backend outlines`),
  `pallama config edit <model>` with in-editor knob hints.
- **Hardened engine store** — per-kind health probes (a config-induced crash
  no longer dethrones a healthy engine), relocatable engine rows, verified
  downloads (no partials, ever), prune-on-update (one engine per lane),
  `engine update --check` dry-run, warm-peg after spawn (the 39.6 tok/s
  concurrency mystery root-caused and fixed), mistral.rs paged-attention
  co-tenancy ladder (no more silent empty responses on shared GPUs),
  strict-manifest `extra_args` (no more silently-ignored engine flags).
- **New knobs** — `model_load_timeout_secs` (raise the 180 s JIT-lane
  budget), `cuda_graph_backend_prefill` (unsticks quantized spawns on
  hybrid-GPU laptops), auto-slots ceiling 8 on ≥ 8 GiB cards.

## Upgrading

1. `sh ./scripts/install.sh` (or rebuild from source) — the installer now
   prints the engine menu (`pallama engine install --kind sglang|mistralrs`).
2. **Restart the daemon** — a running 0.6.0 daemon keeps serving old code.
3. Optional: `pallama config set engine_routing.mode auto` to enable
   per-model engine routing.
4. `pallama doctor` now reports routing rows — unservable models teach the
   install command.
5. `pallama engine update --check` previews upgrades without touching the
   store.

All inference is upstream llama.cpp, mistral.rs and SGLang — the engine
authors did the hard parts.
