# 4. API Specification

<!-- /doc verified against 9e34bafc9f9dc2a59fa2fa81a49b4da9d12feba0+dirty on 2026-09-18 -->

Blazar exposes one gateway with three API dialects (OpenAI, Ollama, Anthropic) plus a CLI. Every route below was verified in `crates/blazar-gateway/src/lib.rs` (router()); every CLI command against `blazar --help`.

## Authentication

- Auth is active **iff at least one `[[keys]]`** entry exists in `config.toml` (or `BLAZAR_KEYS` env). With no keys configured the gateway is open.
- Secret sources, in priority order: `Authorization: Bearer <secret>` header, then `x-api-key` header (Anthropic convention).
- Failure → `401` with body `{"error":{"message":"missing or invalid API key (Authorization: Bearer or x-api-key)","type":"blazar_error","code":401}}`.
- Open (authless) paths: `GET /healthz`, `GET /health`.
- Middleware layer order (outermost→innermost): request-log (trace id `plm-<hex>-<seq>`, echoed as `x-blazar-trace-id`) → auth → CORS → 50 MiB body limit → session pin.
- Per-key limits enforced at admission on every generation lane (text, images, video, audio): `max_concurrent` lease (held until the response body drains), `rpm`, `tpm` (chat-family prompt+completion tokens), `daily_tokens` (UTC day), model scopes (`models` list; empty = all models + admin). Media lanes charge request-count with the lane's own model as scope target (diffusion set / whisper size / piper voice id).

### Streaming transcriptions (`stream=true`)

Progressive transcription over server-sent events, decoded gateway-side:
the uploaded WAV is split at PCM frame boundaries into `whisper_stream_chunk_ms`
windows (default 30 s, range 1-120 s) and each window is transcribed in order on
the same lazy whisper child — a local lane feature (remote audio targets ignore
`stream`). Because the child serializes inference anyway, total throughput is
unchanged; partial text simply arrives while later audio is still decoding.

- Request: multipart with `file`, `model`, and `stream=true` (`1` accepted).
  `stream` and `async` on one body is a 400 request-shape error (checked before
  lane availability). Window-shaping fields the child would honor per-chunk
  (`response_format`, `no_timestamps`, `duration`, `offset_t`) are dropped and
  `response_format=verbose_json` is forced so every chunk reports segments.
- Non-WAV uploads stream as a single chunk (no progressive split possible).
- SSE events (content-type `text/event-stream`, `Cache-Control: no-cache`):
  - `chunk.completed` — `{index, offset_ms, text, segments}` per window;
    segment `start`/`end` are rebased to whole-file time.
  - `transcript.completed` — final `{duration_ms, language, text, segments, chunks}`.
  - `error` — teaching message, then the stream closes.
  - `: keep-alive` comments every 15 s while a chunk decodes.
- Client hangup stops decoding at the next chunk boundary (spent child time is
  bounded by one window).

### On-demand LoRA variants (`model+adapter`)

Any chat/generate/completions/embeddings request may name `model+adapter`
instead of a bare model: the stem matches the file stem of an adapter
attached with `blazar lora add <model> <file>` (colon was rejected as the
separator — it is ollama's `model:tag`). Semantics:

- The variant spawns as its OWN instance (key `model+adapter`), so the
  dense model stays resident and warm — swap per request, no restarts.
- The variant loads ONLY the named adapter (base spelling resolves
  through the usual exact/`:`-swap/prefix ladder first).
- Unknown or duplicated stems 404 with the `blazar lora add` /
  `blazar lora rm` remedy instead of guessing.
- `blazar ps` shows the variant as `model+adapter`; KV session banks,
  prefix heat, and keep_alive matching key the plain model name.
- Spawn-shape options (`options.num_ctx`, `options.spec`) apply to the
  next spawn of the model family — variant or dense, whichever spawns first.
- Router mode does not spawn per-model children: plus-syntax requests
  404 with the `/v1/adapters` alternative (the router child's dynamic
  adapter surface).

### Error model

- `401` invalid/missing key (shape above). `403` management on authless gateway.
- `413` audit body over sniff cap; late-chunking beyond `late_chunking_max_tokens`.
- `422` `sentinel enforce` (non-stream chat; codes + detail + fix hints).
- `502` engine failure (engine text surfaced; dead children reaped so the next request respawns). `503` `all_slots_busy` (bounded queue wait). `400` teaching errors ( unfit ctx pins name all four levers; unknown routes/flags; sglang admission gates — `quant_method` outside the lane's loader set, or a multimodal config missing `preprocessor_config.json`, both name the artifact and the levers pre-spawn). `507` honest memory-floor refusal (`spawn_mem_guard`: MemAvailable < model + floor; message names the numbers and the opt-out).
- Port already bound → daemon exits with code 3 (`RestartPreventExitStatus` for systemd).

## Tool calling and reasoning control

### Tool calling

- OpenAI-compatible: `tools` and `tool_choice` on `/v1/chat/completions` bodies; the preflight only treats a body as tool-bearing when it actually carries a `tools` member.
- `n` choices vs `best_of`: `n` returns ALL N completions in `choices[]` (completions routes); `best_of` judges N generations and returns ONE winner (`/v1/responses`, Anthropic, ollama chat). Different routes, no knob collision. Token accounting: llama-server reports completion tokens per-choice — the gateway multiplies the sniffer charge by `n` for llamacpp lanes (live-probed); streaming and >ENFORCE_BODY_CAP responses skip the count-verify (documented limit). Per-lane engine ceilings surface as the engine's own honest 4xx — live-probed llama-server b11339 caps `n` at 2; the gateway range stays the API contract.
- Ollama-compatible: `tools` array on `/api/chat` (and `/api/generate` where supported).
- Anthropic-compatible: `tools` are mapped to the engine dialect; `tool_choice.type = "tool"` must carry a non-empty `tool_choice.name` (rejected with a teaching error otherwise).
- Tool-call deltas and arguments are translated back into each client's native response shape, so OpenAI, Ollama, and Anthropic SDKs see their own convention.

### Reasoning budget

- OpenAI-compatible: top-level `reasoning_effort` is bridged into the engine's `chat_template_kwargs.reasoning_effort`; an explicit per-request value wins over model config.
- Anthropic-compatible: `thinking.type = "enabled"` with `budget_tokens` maps to the engine thinking budget; `max_tokens` must exceed `budget_tokens` (teaching `400` otherwise). Prior-turn thinking text is preserved across turns where the dialect carries it.
- Per-model default: `reasoning_budget` in the model configuration; unset means the engine template default (auto).
- `Responses API` routes pass `reasoning` through to the engine unmodified — no cross-dialect translation on that surface (chat completions and message routes translate).
- Raw `<think>...</think>` leakage: when a request does not ask for thinking (no thinking controls present), the gateway strips raw think blocks from chat completions responses — buffered and SSE, all three client dialects. Ask explicitly (`think: true`, `chat_template_kwargs.enable_thinking`, `enable_thinking`, or a non-off `reasoning_effort`) and the reasoning ships intact.
- mistral.rs engines expect top-level `enable_thinking` (bool) and `reasoning_effort` (`off|low|medium|high|xhigh`), and default thinking ON when both are omitted. On chat routes the gateway injects `enable_thinking: false` for control-free requests (fast answers by default), aligns top-level controls with `chat_template_kwargs` when both are present, and maps OpenAI effort names (`minimal`→`off`, `max`→`xhigh`).
