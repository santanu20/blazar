# 4. API Specification

<!-- /doc verified against 9e34bafc9f9dc2a59fa2fa81a49b4da9d12feba0+dirty on 2026-09-18 -->

Blazar exposes one gateway with three API dialects (OpenAI, Ollama, Anthropic) plus a CLI. Every route below was verified in `crates/blazar-gateway/src/lib.rs` (router()); every CLI command against `blazar --help`.

## Authentication

- Auth is active **iff at least one `[[keys]]`** entry exists in `config.toml` (or `BLAZAR_KEYS` env). With no keys configured the gateway is open.
- Secret sources, in priority order: `Authorization: Bearer <secret>` header, then `x-api-key` header (Anthropic convention).
- Failure → `401` with body `{"error":{"message":"missing or invalid API key (Authorization: Bearer or x-api-key)","type":"blazar_error","code":401}}`.
- Open (authless) paths: `GET /healthz`, `GET /health`.
- Middleware layer order (outermost→innermost): request-log (trace id `plm-<hex>-<seq>`, echoed as `x-blazar-trace-id`) → auth → CORS → 50 MiB body limit → session pin.
- Per-key limits enforced at admission on every generation lane (text, images, video, audio): `max_concurrent` lease (held until the response body drains), `rpm`, `tpm` (chat-family prompt+completion tokens), `daily_tokens` (UTC day), model scopes (`models` list; empty = all models + admin). Media lanes charge request-count with the lane's own model as scope target (diffusion set / whisper size / piper voice id).

### Keys management [ADMIN]

Authless gateways REFUSE management (403, teaching message). Only unscoped keys (empty `models` = admin) may manage.

| Method + route | Purpose |
|---|---|
| GET `/api/keys` | list keys (secret redacted to prefix8+`…`; usage per UTC day) |
| POST `/api/keys` | add: name charset `[A-Za-z0-9._-]` else 400; 409 on duplicate; `rpm`/`tpm`/`daily_tokens`/`max_concurrent` validated non-negative (default 0), `weight` default 1; secret = `plm_` + 32 hex, shown ONCE |
| DELETE `/api/keys?name=` | remove; 404 unknown; 409 refusing to remove the last key (would leave the gateway authless) |
| POST `/api/keys/rotate?name=` | new secret (old dies immediately); name/scopes/limits/usage kept |

Persistence: full-file `config.toml` round-trip (parse→swap→validate→atomic temp+rename, timestamped `.bak`) under a process-wide lock; registry rollback on persist failure.

### Request headers (blazar extensions)

| Header | Purpose |
|---|---|
| `Authorization: Bearer` / `x-api-key` | auth secret |
| `x-blazar-trace-id` | echoed trace id |
| `X-Blazar-Priority` | `high`/`low` (case-insensitive; else Normal) — EDF queue tiers 2 s/30 s/120 s |
| `X-Blazar-Deadline-Ms` | strict deadline (never WFQ-delayed) |
| `X-Blazar-Num-Ctx` | per-request ctx on the OpenAI path (restart-once semantics) |
| `X-Blazar-Spec` | per-request spec mode on the OpenAI path (`off`/`auto`/`eagle3`/... — same semantics as `options.spec`; same-shape = no restart) |
| `X-Blazar-Enforce` | `1`/`0` per-request sentinel hard mode (422 on violations, non-stream chat) |
| `X-Blazar-Session` | session pin (holds eviction for `session_keep_secs`) |
| `X-Blazar-Model` | engine-scoped surface model selection |
| `X-Blazar-Cache` | semantic cache override: `on`\|`off`, `-ttl 1..=86400`, `-threshold 0.01..=1.0` |
| `x-blazar-remote` | names the remote-pool member that served |

### On-demand LoRA variants (`model+adapter`)

Any chat/generate/completions/embeddings request may name `model+adapter`
instead of a bare model: the stem matches the file stem of an adapter
attached with `blazar lora add <model> <file>` (colon was rejected as the
separator — it is ollama's `model:tag`). Semantics:

- The variant spawns as its OWN instance (key `model+adapter`), so the
  dense model stays resident and warm — swap per request, no restarts.
- The variant loads ONLY the named adapter (base spelling resolves
  through the usual exact/`:`-swap/prefix ladder first).
- Unknown or duplicated stems 404 with the `blazar lora add` /
  `blazar lora rm` remedy instead of guessing.
- `blazar ps` shows the variant as `model+adapter`; KV session banks,
  prefix heat, and keep_alive matching key the plain model name.
- Spawn-shape options (`options.num_ctx`, `options.spec`) apply to the
  next spawn of the model family — variant or dense, whichever spawns first.
- Router mode does not spawn per-model children: plus-syntax requests
  404 with the `/v1/adapters` alternative (the router child's dynamic
  adapter surface).

### Error model

- `401` invalid/missing key (shape above). `403` management on authless gateway.
- `413` audit body over sniff cap; late-chunking beyond `late_chunking_max_tokens`.
- `422` `sentinel enforce` (non-stream chat; codes + detail + fix hints).
- `502` engine failure (engine text surfaced; dead children reaped so the next request respawns). `503` `all_slots_busy` (bounded queue wait). `400` teaching errors ( unfit ctx pins name all four levers; unknown routes/flags).
- Port already bound → daemon exits with code 3 (`RestartPreventExitStatus` for systemd).

## CLI

`blazar <COMMAND>` — grouped as in `--help`. Flags before the prompt for `run`; `--json` where noted emits machine-typed JSONL on pure stdout.

### Serve & chat

| Command | Purpose |
|---|---|
| `serve` (alias `start`) | run the daemon in the foreground (all three APIs on one port) |
| `run <model> [prompt...]` | chat REPL / one-shot; auto-pulls missing model; flags must precede prompt (leading `-` needs quoting or `--`); `-v` eval counts; `--max-tokens` single-shot only; REPL slash-commands: `/exit` `/clear` `/model` `/sysinfo` `/profile` |
| `ps` | live instances: state, ctx, in-flight, idle countdown (`--reset` breaker clear, `--json`) |
| `stop [model]` | stop daemon; with model = unload that model now |
| `launch COMMAND` | exec an agent CLI against the daemon (sets base-URL env; `--warm`, `--key`) |
| `session save/restore/rm/list` | slot KV checkpoints per model (survive unload/restart) |

### Model management

| Command | Purpose |
|---|---|
| `pull <target>` | `owner/repo[:QUANT]` or catalog shortname; `--force` format-flip replace; `--verify` re-hash the pulled file against its recorded sha256 instead of pulling (single-file rows; dir rows refused) |
| `import <path>` | import existing GGUF (hardlink default; `--name --quant --copy --mmproj`) |
| `cp` | zero-byte hardlink alias |
| `create` | Modelfile alias (FROM + PARAMETER num_ctx + ADAPTER → config overlay, no blob copy) |
| `rm <models...>` | remove (refuses while running) |
| `list` / `ls` | list models (`--json` JSONL) |
| `show <model>` | details, active profile, last benchmark (`--json`) |
| `quantize` | derive quantization via engine llama-quantize (`-t`, `--imatrix`, `--verify` perplexity gate, `--max-degradation`, `--allow-requantize`) |
| `mmproj` | attach vision projector (refuses while running) |
| `search` | HF search (every format `--format any`, `--quant <q>`, `--json`) |
| `fit <target>` | pre-download VRAM/RAM fit preview + quant alternatives (`--json`) |
| `lora add/rm/list` | LoRA adapter management |

### Tuning & benchmarks

| Command | Purpose |
|---|---|
| `bench <model>` | pp/tg benchmark (history feeds tune gates) |
| `tune <model>` | `--search` grid argmax; live probes `--slots`/`--ngram`/`--load`/`--replicas`/`--cache-reuse`; `--ctx`, `--spec` |
| `drafts <model>` | speculative draft candidates (EAGLE3/MTP + small same-family) |
| `coreside` | VRAM co-residency plan (hot-first greedy) |

### Engine & config

| Command | Purpose |
|---|---|
| `engine update` | install + activate upstream engine (sha256-verified, regression-gated; `--kind`, `--tag`, `--check`, `--no-gate`) |
| `engine build cuda\|cpu` | source build (auto GPU-arch, host-compiler match; `--arch`, `--jobs`); `--fork owner/repo@<sha>` / `--repo` + `--ref` builds a pinned capability lane (immutable commit, architectures mined from source, provenance in `engine list`) |
| `engine offers` | curated capability-lane registry catalog (`--arch`, `--json`, BACKENDS column; `--backend` on install must be one the lane advertises; disabled via `capability_registry_url = ""` or `BLAZAR_CAPABILITY_REGISTRY=""`) |
| `engine install --lane <id> [--backend cpu\|cuda]` | build a curated registry lane (validators re-run, curated trust, backend must be advertised, auto-retire after `fork_retire_days` once upstream covers its archs; user pins protect) |
| `engine list/use/rm/prune/rollback/local/install` | roster management (`--json`; rm refuses the active engine AND any engine with a live child serving it — names the models and teaches `blazar stop <model>`; with the daemon down it refuses on leftover child pidfiles and teaches the boot orphan sweep; prune by retention policy; `local` = pseudo-tag). Fork lanes are additive: never pruned, no retention budget; `--json` rows gain `source` + `provenance` + `superseded_by` |
| `config list/get/set/unset/defaults/edit` | config.toml management (dotted keys; quoted segments stay one segment; root-scope-only unset) |
| `keys list/add/rm/rotate` | key management against the running daemon |
| `whisper` | transcription + whisper lane management (`--install --pull --list --pin --model --tag`) |
| `doctor` | grouped diagnostics SYSTEM/GPU/ENGINES/MODELS/CHANNELS/RUNTIME (`--flat`, `--json`) |
| `migrate` | legacy `api_keys` → `[[keys]]` (idempotent, backup) |
| `snapshot` | config+store+sessions backup to timestamped dir |
| `upgrade` | self-update (sha256-verified; `--version`, `--dry-run`) |
| `completions bash\|zsh\|fish\|powershell` | shell completions to stdout |

### Observability

| Command | Purpose |
|---|---|
| `why [trace]` | sentinel detections for a trace (or latest) with fix hints (`--code`, `--model`, `--limit`, `--watch`) |
| `watch` | live tail of sentinel detections |

### Refused by design (local-only)

`push`, `signin`, `signout`, `login`, `logout` — all refused: no registry push, no cloud accounts.
