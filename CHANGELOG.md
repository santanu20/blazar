## [0.23.0] - 2026-10-08

### Added

- **RPC fleet lane: one daemon, many machines.** Any spare box can now join the serving fleet. `blazar rpc worker` proxies a stateless llama.cpp RPC worker (the engine binary speaks the ggml RPC protocol; the worker owns process lifecycle and shuts down cleanly on INT 130 / TERM 143 / HUP 129), and `blazar rpc status` introspects the whole fleet over the same wire protocol — backend version, reachability, and per-device host + VRAM totals, not just a ping. Fit verdicts (the admission belt, the impossible-floor refusal, and the J3 free-VRAM preflight) now count reachable workers' device totals into the machine's capacity budget, with a 10 s reachability cap; unreachable workers warn and skip instead of failing the check. Because the engine maps its device indices onto the RPC-first order, automatic tensor-split emission is suppressed whenever `rpc_servers` is configured (a manual split still rides through). `blazar doctor` gains a fleet check that cross-links `rpc status` output for triage. Config: global `rpc_servers` and per-model `model_overrides.<model>.rpc_servers`.
- **Per-model `tensor_split` overlay.** `model_overrides.<model>.tensor_split` now overrides the global `tensor_split` ratios for that one model (empty value inherits the global, mirroring the rest of the overlay family; validation is shared). Emission stays behind the lane's `--tensor-split` capability gate, and the planner gates — manual-split-spanning, parallel-pins-unset, and the auto-planner stand-down — read the effective pin, so a model-scoped split gets exactly the treatment a global one always had. The F2 rpc battery proves the overlay reaches the child argv (`--tensor-split 3,1` alongside `--rpc`).
- **`blazar certify` and Passport v1.** One command refreshes stale evidence (benchmarks and model-doctor runs via the autopilot staleness core; tuning is noted, never auto-run), then assembles a Passport v1 JSON document — identity, engine, hardware, profile, measured performance, capabilities, and verification chains — with absent axes as explicit nulls rather than missing keys. The human-readable card is a projection of the same JSON, so the two cannot drift; progress streams to stderr so `--json` output stays machine-clean.
- **Evidence axes on every benchmark row (schema v13).** `model_caps`, `bench_results`, and `bench_history` gain nullable quant, hardware-fingerprint, workload, and profile-hash columns, making every row self-contained evidence you can GROUP BY directly in SQL. Rows written by older binaries simply carry empty axes.
- **Decode-throughput prediction from measured bandwidth.** When `blazar plan` meets a model with no measurement of its own, it calibrates effective bandwidth as the median of `tps × model_bytes` over the relevant bench history and predicts decode t/s as bandwidth ÷ target-bytes — stating the sample count and lane basis next to the number, and clamping to [0.05×, 20×] of the fastest sample so a stale or mismatched history cannot run away.
- **TypeScript SDK.** `sdk/ts` ships a zero-dependency `blazar-sdk` covering the chat, streaming, and ops surfaces — the same API coverage as the Python SDK for Node and browser clients.
- **Scorecard as a per-axis execution vector.** The scorecard composes bench and capability evidence into a per-axis execution vector instead of a scalar, so a high aggregate cannot hide a weak leg. `blazar plan` decision axes are labeled with their evidence class, and model-doctor evidence counts now accumulate across certificate runs.
- **Four-dialect conformance suite + proptest tier.** One semantic request is driven through OpenAI chat, Anthropic messages, Ollama chat, and Ollama generate and must return the same text and the same token accounting (`usage.prompt_tokens`, `usage.input_tokens`, `prompt_eval_count` are translation, not divergence) — streaming deltas included; the Responses surface is held to shape + status smoke. Below it, a proptest tier (proptest 1.11) pins the GGUF parser and image-URL translation invariants.
- **Stable error codes + `GET /api/errors` catalog.** Every gateway-rendered OpenAI-shaped error now carries a `blazar_code` string (`MODEL_NOT_FOUND`, `ENGINE_CIRCUIT_OPEN`, `INSUFFICIENT_MEMORY`, …) that is additive-only and never renames or renumbers, alongside the existing `message`/`type`/`code` fields (numeric `code` stays the HTTP status). Typed choke points (supervision lifecycle, admission/preflight teaching refusals, auth and key-budget middleware, host guard) emit precise codes; all other `openai_error` sites derive a generic-but-stable code from the status, so the field is present on every path. `GET /api/errors` serves the machine-readable versioned catalog, and `docs/error-codes.md` mirrors it behind a drift-pin unit test. Engine-child errors forwarded verbatim and the Ollama-dialect lane keep their own shapes.
- **MCP stdio sandbox options.** `[[mcp]]` servers can now declare `env_clear` (start the child from an empty environment instead of inheriting the daemon's), `allowed_env` (the only parent variables it may re-inherit), `cwd` (pin the working directory), and `max_output_bytes` (cap on one stdout protocol message, minimum 1024). Invalid combinations are refused at boot with teaching errors (e.g. `allowed_env` without `env_clear`, sandbox options on a url server). stdio children's stderr is now piped and logged at `warn` with a hard bound (first 32 KiB per server) instead of being discarded. Existing configurations behave exactly as before: every option is opt-in and defaults off.
- **Grouped config sections (optional spelling).** `config.toml` may group related flat keys under `[gateway]`, `[routing]`, `[resources]`, `[speculative]`, `[diffusion]`, `[whisper]`, `[vision]`, `[yarn]`, `[reasoning]` or `[observability]`; the loader hoists them onto the same flat keys before parsing. Root-plus-section double-spelling and keys placed in the wrong group are refused with teaching errors; unknown groups remain hard errors; the flat form stays canonical for every tool.

### Fixed

- **Whisper 501 check no longer fails a live lane.** The teaching contract (501 + install/pull hint) is only observable when the whisper engine or a model is missing — on a box with both present the lane transcribes (200) and the live-validation check misfired as a hard failure. The engine-tag scan is hoisted to module scope (`whisper_tags`) and guarded by `whisper_lane_live()`, so the live-box case boundary-skips with a named reason. Live-proven: wave phase 32 pass / 2 boundary / 0 fail (was failing status=200).
- **Python SDK default port.** The SDK defaulted to Ollama's 11434; it now points at Blazar's 11435 out of the box, so a fresh install talks to the daemon without configuration.
- **Windows clippy gate.** The non-Unix branch of `rpc_worker_shutdown` tripped `clippy::map_unwrap_or` on the 1.98 Windows toolchain (both lints fire on the `map(..).unwrap_or(..)` chain). The ctrl_c await now discards its result and the handler returns the conventional 130 (128 + SIGINT) directly, matching the Unix branch.

### Changed

- **Schema-level one-active-engine invariant.** The `engines` table now carries a partial unique index (`one_active_engine` on `active WHERE active = 1`), so overlapping active flags are rejected by SQLite itself, not only by transaction discipline in `set_active_engine`. Legacy stores that somehow accumulated double-active rows are repaired at migration (keeper picked by the same lane preference `heal_active_engine` uses; all-lazy actives land at zero-active). Upserting an engine row with `active = true` now demotes any other active row in the same transaction — production paths already activated exclusively through `set_active_engine`, so observable behavior is unchanged. Declared foreign keys stay deliberately out: model-keyed evidence tables (bench history, capability certs, results, profiles) must outlive model deletion, and `job_events` already cascades manually in the correct order. Schema note: the evidence-axes migration lands as `user_version` 13 and this one as 14 on the integrated tree.
- **Release assets now carry SLSA provenance + CycloneDX SBOM attestations.** The release workflow attests every binary with GitHub artifact attestations (SLSA build provenance via `attest-build-provenance`, plus a CycloneDX 1.5 SBOM), so consumers can verify what was built and from which sources.
- **Install lanes and crates.io presentation.** `cargo binstall blazar` is documented as the prebuilt-binary lane alongside `cargo install`; README assets moved to absolute URLs so the crate page renders them; the crate readme points at the repository root; docs adopt a local-first framing across identity surfaces.
- **Gateway-overhead campaign receipts.** The 2026-10-07 overhead campaign's raw cells, plots, and run receipts are committed under `bench-artifacts/2026-10-07-overhead/` alongside the curated report, so the numbers can be re-analyzed without re-running the campaign.

## [0.22.0] - 2026-10-07

### Added

- **Python SDK on PyPI as `blazar-sdk`.** `pip install blazar-sdk` now installs the zero-dependency client (the import package stays `blazar`; PyPI's `blazar` belongs to the unrelated OpenStack reservation service). Packaging fixed along the way: the distribution was still declared `blazar` at version 0.1.0 while the code was 0.3.1 — the version is now single-sourced from `blazar/__version__` so packaging can never drift from code again. A dedicated `sdk-v*` tag lane (own version line, independent of the Rust workspace releases) builds the wheel, import-smokes it on a clean interpreter, publishes via PyPI trusted publishing (OIDC — no tokens stored anywhere), and verifies the public PyPI JSON API serves the tagged version before going green.
- **RoPE frequency and checkpoint-spacing knobs.** `rope_freq_base`, `rope_freq_scale` and `checkpoint_min_step` are first-class config keys (global and per-model overlay), pushed to llama.cpp lanes via the gated flags `--rope-freq-base`, `--rope-freq-scale` and `--checkpoint-min-step`. `None` (the default) keeps the values baked into the checkpoint. `validate.py` covers the new knobs with fixtures.
- **Checkpoint-declared quantization in the CLI.** `blazar model list/show/json` for safetensors checkpoints now read `quant_method` from the model's config.json (top-level or `quantization_config` nesting; torchao/awq/gptq) instead of guessing from the directory name — the name-derived column reported torchao int4 checkpoints as BF16. GGUF and MLX models are unaffected.
- **Config documentation drift gate.** `scripts/check_config_doc_drift.py` parses the `Config` struct fields (brace-depth, comment-aware) and fails CI when `docs/config-code-paths.md` (now 205 fields) falls out of sync with the code.
- **Remote URL scheme ladder.** `[[remotes]]` URLs are classified at boot: `https://` accepted everywhere; cleartext HTTP accepted on loopback, warned on private/LAN addresses, and refused for public hosts or hostnames (hostname ≠ `localhost` counts as public — no DNS at validation). Per-remote `allow_insecure_http = true` downgrades the refusal to a loud warning for labs that must reach a legacy cleartext endpoint.

### Fixed

- **mmproj VRAM no longer double-charges the offload envelope.** The auto GPU-offload solver reserved projector bytes even when the vision projector was deliberately held back for lazy attach, pushing real 8 GiB-card demand into the under-offload band (a 5878 MiB model profile landed as ~999 layers-off). `resolve_gpu_offload` now charges mmproj bytes only when the projector actually rides the spawn (explicit `-mm`, `mmproj_force`, Attach policy, or engine flag), keeping the 85% pin envelope honest. Pinned by `unit__gpu_layers_pin_ignores_held_back_mmproj`.
- **mistral.rs lane: hard guard + grammar + vocab teaching.** Multi-ordinal `device_layers` on a single-GPU machine now fails at profile compile with an actionable message (the engine previously died at load with none). `pa_cache_type` is validated against the installed mistral.rs grammar (`auto`, `f8e4m3`) at config-write time. Llama.cpp-only knobs set on mistral.rs/MLX/SGLang models are now taught via `llama_vocab_knobs_set()` vocabulary teaching instead of silently no-oping, and the MLX profile carries the resulting warnings.

### Changed

- **Public cleartext-HTTP remotes are refused at boot.** A `[[remotes]]` entry pointing at a non-private `http://` host previously booted silently with its bearer key exposed on the network path; the scheme ladder now refuses it with a teaching error (escape hatch: that remote's `allow_insecure_http = true`, or use `https://` / an IP literal). Loopback and LAN HTTP remotes keep booting — LAN gains a warning line in the daemon log. Note for downgrade: an older binary reading a config that sets `allow_insecure_http` fails on the unknown field — remove the key when rolling back.
- **Slot adoption cap raised 8 → 16.** The supervisor's adopt cap is a scheduling policy, not a VRAM guard; at 8 it was the binding constraint under 16-stream load. Tests rescaled to the new cap.
- **Benchmark suite refresh.** Chart/matrix/selftest pipeline rework; two new Oct 6 campaigns (`20261006-matched-conc`, `20261006-perf-lanes`) with full reproducibility receipts; regenerated plots and reports for prior campaigns; INDEX/BENCHMARK/README tables refreshed (1.4% gateway overhead, ITL p99 25.8 ms vs 75 ms for Ollama, 96.3 t/s at C8 matched-slots).

### Removed

- **Dead helpers `effective_lazy_mode` / `effective_spec`.** Both lost their last callers (verified by repo-wide search); their unit tests went with them.

## [0.21.1] - 2026-10-06

### Fixed

- **Concurrent config writes on Windows.** `persist_config` could fail one writer with a Windows sharing violation in two ways: two writers inside the same millisecond collided on one backup path (`config.toml.bak-<ms>`), and the copy/rename pair had no tolerance for a file being briefly held open by antivirus, the search indexer, or a concurrent writer — Windows, unlike POSIX rename, refuses the replace while that lasts. Backup names are now unique per writer (pid + per-writer counter), and copy/rename retry `ERROR_SHARING_VIOLATION` a bounded 8 times with linear backoff before surfacing the error unchanged. POSIX paths are untouched (the retry check only matches on Windows). Pinned by the concurrent-writers test, green on Linux, macOS, and Windows CI.
- **Release pipeline: draft-release healing.** Re-pushing a tag (delete + re-create) makes GitHub drop the existing release to a draft, and the asset-upload path never re-published it — v0.21.0 sat invisible with v0.20.0 still marked Latest until it was healed by hand. `release.yml` now clears the draft flag after every upload/create and claims `latest` when the tag is the repository's newest.

## [0.21.0] - 2026-10-06

### Added

- **Bare rerank alias routes + census truth (audit 2026-10-06).** llama-server documents `POST /reranking` as canonical with `/rerank` as its alias; upstream-native clients calling the bare (no `/v1`) spellings got a 404. Both are now mounted on the same passthrough lane as the prefixed forms (one endpoint, four spellings — pinned end-to-end by a compat test against the live forwarding path). The inventory drift guard got teeth: `aliases` entries in `docs/upstream-api-inventory.json` were display-only — `scripts/validate.py --phase=inventory` now fails when a listed alias is not a mounted route. The `/api/version` endpoint census also lagged the router: `POST /v1/chat/completions/{id}` (chat-completion update) was routed since the OpenAI-parity wave but never advertised; the census now carries it alongside the bare rerank spellings.
- **Native llama-server surface parity (audit 2026-10-05).** Two upstream routes were unrouted and one dialect bug fixed. `POST /completion` (native prompt completion, no `/v1` prefix) and `POST /embeddings` (native token-level batch dialect, `pooling=none`) are now mounted on the OpenAI forwarding lane — llama-server clients work against Blazar unmodified. Bug fix: `openai_proxy` hard-400'd model-less bodies, but upstream bodies on `/infill`, `/v1/systemone`, `/completion`, and `/embeddings` carry no `model` field (router-mode-only there) — direct-server clients posting them bare got rejected where direct llama-server accepts them. These native paths now resolve their target with the same chain as the engine-scoped surfaces (`X-Blazar-Model` > `?model=` > single hot child, extracted into shared helpers); OpenAI-dialect paths keep the hard 400 — silence there would route a typo to the wrong lane. The `/api/version` endpoint census carries the two new routes. To keep the surface from drifting piecemeal again, `docs/upstream-api-inventory.json` pins the upstream llama-server endpoint set (source + date) and `scripts/validate.py --phase=inventory` fails on any pinned endpoint that is neither mounted in the router nor explicitly exempted with a reason (38 checks green; exemptions: router-mode `/models*` management, legacy `/embedding` alias, upstream web UI).
- **Engine boot-flags: `sdcpp_extra_args` + `whisper_extra_args`.** Two config keys (and `BLAZAR_SDCPP_EXTRA_ARGS` / `BLAZAR_WHISPER_EXTRA_ARGS` env overrides, comma-separated) append extra boot flags to the sd-server and whisper-server children. The sdcpp tier rides ahead of per-model `extra_args` — engine last-wins, so a duplicate flag resolves to the model override with a compile warning naming the duplicate — and is the first-class lever for boot-time model addons (`--control-net`, `--ip-adapter`, `--photo-maker`, `--motion-module`, `--upscale-model`, `--lora-model-dir`, `--hires-upscalers-dir`, `--audio-vae`/`--audio-encoder`, …). Both tiers pass the same reserved-pin and probed-manifest gates as the overlay. A `--backend` in the config tier owns device posture (the auto weight-split stands down — pinned live via `/proc/<child>/cmdline`: `--backend cpu` present exactly once, no `diffusion=` split token). The whisper tier appends after the pinned loopback/port/model/VAD argv and gate-checks every flag against the child's own `--help` surface at compile — a misspelling fails fast with a teaching error instead of a silently dead child; `--host`/`--port`/`--model`/`--vad`/`--vad-model` are reserved. Unset keys reproduce today's argv byte-for-byte.
- **Streaming lossy TTS.** `"stream": true` on `/v1/audio/speech` with a lossy `response_format` (`mp3`/`opus`/`aac`/`flac`) now streams live: each sentence is synthesized raw from piper (`--output_raw` at the voice's own sample rate, read from its voice json) and fed into a single persistent ffmpeg pipe (s16le → codec → muxer), so encoded bytes flow as they are produced — first audio arrives with the first sentence (~1 s on the rig) instead of after the whole clip transcodes. `wav` + stream teaches 400 (a WAV header needs total lengths up front — `pcm` is the raw streaming format), `pcm`/`pcm16` stream exactly as before, and the default without `stream` remains a fully-buffered byte-identical body. Client hangup kills the ffmpeg child (kill-on-drop); zero lingering piper/ffmpeg processes verified after every run. Live receipts for all four streaming formats (ID3 mp3, OggS opus, fLaC, ADTS aac magics) in `bench-artifacts/20261005-tts-stt-video-sota/` alongside a 10-cycle stream/stream/buffered hammer (30/30 clean).
- **Crash-window closure on the image/video job planes.** If an async image or video job's engine child dies mid-flight (admission eviction, crash, restart), the row used to wedge forever in `queued`/`in_progress` while `GET /v1/images/jobs/{id}` answered a misleading 404 ("no live diffusion child serves jobs") for a job that existed. Now the lane pollers and the Sora views (`GET /v1/videos/{id}`) close the orphan on first poll: the row flips to `failed` with a "child is gone — resubmit" hint, terminal rows keep serving from the durable ledger with no live child, and cancel works against the ledger when no child is alive. Live-pinned all three ways on a rig (admission-evicted image row, `kill -9` mid-generating video row, terminal row with no child).
- **Video mid-run previews: probed-negative.** The Sora `partial_images`/mid-render-preview surface stays a teaching 400, now with a probe receipt instead of an assumption: polled a live sd-server child mid-`vid_gen` — the job object carries `status`/queue position only (no progress fraction, no preview bytes), `/sdapi/v1/progress` and `/health` answer 404 on this build. `GET /v1/videos/{id}` therefore reports `progress` as 0-while-queued/100-at-completion only, and the API spec says so. Re-probe when an engine build grows a progress surface.
- **Operator switch: `BLAZAR_VRAM_OVERCOMMIT=0`.** The per-request `"vram_overcommit": true` escape hatch on video generation can now be disabled centrally: with the env set to `0`/`false`/`off`/`no`, requests pulling the lever get a teaching 400 naming the remaining levers, and the VRAM scratch refusal stops suggesting the disabled lever (an unset or unrecognized value leaves it enabled — posture never flips silently). Live-receipted both ways on a rig daemon: lever request → 400 teach, over-budget request without the lever → refusal ending "the vram_overcommit lever is operator-disabled".
- **Job-prune artifact cleanup.** `prune_jobs` (the 7-day terminal-row retention sweep at boot) now returns the spilled artifact paths of the rows it deletes, and the boot sweep removes those files best-effort (logged on failure, never fatal) — a pruned row's multi-MB render no longer lingers as an unreachable orphan in the jobs spill dir. Live probe artifacts for the whisper tdrz follow-up also landed: on a real tdrz model (`ggml-small.en-tdrz`), `tinydiarize` and `dtw` as per-request form fields show no observable effect on this engine build — both stay un-whitelisted as probed-negative (receipts `stt-tdrz-probe-*.json`).
- **STT diarization: `response_format=diarized_json`.** Stereo input (one voice per channel) now returns the OpenAI diarized shape `{duration, text, segments[].{id, start, end, text, speaker}}`: the gateway forces the child into verbose_json + `diarize=true`, strips the engine's `(speaker N)` text prefixes, rebuilds the joined `text`, and passes each segment's `speaker` through verbatim. If the child returns nothing mappable the route answers a teaching 502 — never a wrong shape under the diarized_json name. The stream lane teaches 400 (SSE carries no speaker labels). Live-probed on the whisper child: `diarize=true` and `no_language_probabilities=true` are accepted form fields (both now whitelisted — the latter drops `language_probabilities` from verbose_json), while `tinydiarize`/`dtw` showed no observable effect on this model and stay unlisted. `transcriptions`/`translations` treat `diarized_json` as a first-class format, async jobs replay the mapped body, and `/v1/audio/capabilities` documents the new format and shape.
- **Python SDK 0.3.1 — `Client.transcribe`.** Zero-dependency multipart transcription: `transcribe(path, model=..., response_format=..., **knobs)` uploads any local audio file, sends list kwargs (e.g. `timestamp_granularities`) per-value OpenAI-style, returns a dict for the JSON family (verified live: two-speaker `diarized_json`, word-timed `verbose_json`) or the raw string for `text`/`srt`/`vtt`. TTS `opus`/`aac` transcodes verified live alongside (`audio/ogg` + OggS magic, `audio/aac` + ADTS magic), completing the lossy-family receipts.
- **`/v1/audio/speech` full format family + `/v1/audio/voices`.** TTS now speaks the OpenAI format surface: `wav` stays the default (documented deviation — OpenAI defaults to mp3), `pcm`/`pcm16` stream as before, and `mp3`/`opus`/`aac`/`flac` are transcoded through optional system `ffmpeg` — argv built gateway-side from a fixed enum (client strings never reach the process), 60 s budget → 504, ffmpeg failure → 502 with the stderr tail, absent binary → teaching 400 naming wav/pcm and the install hint. Native piper knobs (`speaker`, `noise_scale` 0..2, `noise_w` 0..2, `sentence_silence` 0..10 s) ride the request alongside `speed`; `instructions` gets an honest teaching 400 (voices are fixed personalities). New `GET /v1/audio/voices` lists installed voices (`{id, language, name, quality, installed}`) and `?search=` adds a HuggingFace voice search — URL-encoded, length-capped, 20 s budget, results capped at 50 with a `truncated` flag; a failed or timed-out search still returns the installed list with a `search_error` note.
- **STT word timestamps + engine-knob surface.** `/v1/audio/transcriptions` and `/translations` honor `timestamp_granularities[]` (`word`/`segment`, array or comma form): it forces `verbose_json` (an explicit different format is a teaching 400) and `word` switches the child into token-timestamp mode — the gateway derives per-segment `words[]` from token timings with SentencePiece-aware grouping, omitting untimed words rather than interpolating; the `x-blazar-word-timestamps: derived|unavailable` header states which happened. The forwarded-field whitelist grows by ten binary-verified engine knobs: `token_timestamps`, `suppress_non_speech`, `suppress_nst`, `vad_simple`, `vad_threshold`, `vad_min_speech_duration_ms`, `vad_min_silence_duration_ms`, `vad_max_speech_duration_s`, `vad_speech_pad_ms`, `vad_samples_overlap`. Cloud-only fields (`include`, `keywords`, `response_format=diarized_json`) teach 400 with the local menu. Async jobs record the request granularities and replay the enriched body; srt/vtt/text stay byte-verbatim relays.
- **Images: `quality`/`style`/`output_format` + `/v1/images/variations`.** OpenAI `quality` (`low`/`medium`/`high`/`xhigh`/`max`/`auto` plus `standard`/`hd` synonyms) scales `sample_steps` relative to the family's own default — fetched live from the child's capabilities and cached 10 min, never a hardcoded step count; explicit `steps` + `quality` is a teaching 400 (two dials for one knob). `style` (`vivid`/`natural`) presets `guidance.txt_cfg` for curated families and teaches elsewhere with the native knob named. `output_format` (`png`/`jpeg`/`webp`) validates per lane and passes through; `response_format: url` teaches `b64_json` (no asset hosting); `moderation`/`partial_images`/`background`/`input_fidelity` teach 400 honestly. New `POST /v1/images/variations`: the multipart `image` becomes a native img2img call (`init_image`, random seed, optional prompt with digit prompts preserved as strings), typed fields coerced (`n`, `seed`, `strength`, `output_format`, …), stray file parts steered to `/v1/images/edits`, and the same admission/teaching/`async`/`stream` job modes as generations.
- **Sora verbs on `/v1/videos`.** `POST /v1/videos` accepts `seconds` (`"4"`/`"8"`/`"12"` or int — Sora's spelling) alongside native fields: frames = seconds × effective fps, fps taken from the child's vid_gen capabilities default when the client leaves it unset, normalized to the engine's 4n+1 cadence (the completed result's `frame_count` is the truth and feeds the echoed `seconds`). `GET /v1/videos` lists the durable video-job plane Sora-shaped (`object: "list"`, `first_id`/`last_id`/`has_more`); `GET /v1/videos/{id}` serves the Sora video object (status vocabulary mapped, `progress` when the live child reports it); `GET /v1/videos/{id}/content` returns the finished container bytes under the job's own mime (`video/webm`, animated `image/webp`, `video/x-msvideo`) — 404 until completed, 410 when pruned; `DELETE /v1/videos/{id}` cancels (best-effort on the live child, ledger marked) and answers `{object: "video.deleted", deleted: true}` idempotently. `remixed_from_video_id` teaches — no local I2V-from-video. Every Sora verb rides the existing durable jobs ledger; no parallel subsystem.
- **Realtime v2 events.** `/v1/realtime` grows: `session.update` (voice/stt_model/instructions validated, applied from the NEXT turn, `session.updated` echo), `input_audio_buffer.clear` (`…cleared` confirmation), `response.create` (force a turn on the buffered audio), `response.cancel` (silent flag honored between pipeline stages — the in-flight chat stream itself is not mid-cancellable, documented; both checkpoint outcomes emit `response.cancelled` with a `transcript_delivered` marker when text already shipped), `conversation.item.create` (text items feed later turns as context, bounded 16 items / 8192 chars oldest-evict, `conversation.item.created` echo with server-assigned id), and structured `input_audio_transcription.failed` alongside the legacy error event. The original six-event contract stays byte-stable; out-of-band events during a running turn get a teaching error instead of being dropped.
- **Python SDK 0.3.0 — media methods.** `Client.voices(search=None)` lists installed (+ remotely searched) TTS voices; `Client.speech(voice, text, response_format=..., **native)` returns `(content_type, audio_bytes)` covering the full wav/pcm/pcm16/mp3/opus/aac/flac family with the native piper knobs passing through as keywords. ## [0.20.0] - 2026-10-03

### Security

- **Loopback gateway hardened against browser-borne attacks (DNS rebinding + cross-origin).** When bound to a loopback address the gateway now validates the `Host` header (localhost names, local/private/link-local IP literals, `*.localhost`/`*.local`/`*.internal`, machine hostname; anything else gets a 403, preflights and `/health` stay open) — the same defense ollama shipped for CVE-2024-28224 — and the CORS default flipped from deny-all to a local-origin allowlist: `localhost`, `127.0.0.1`, `[::1]`, `0.0.0.0` on any port plus desktop-webview schemes (`app://`, `file://`, `tauri://`, `vscode-webview://`, `vscode-file://`) are always allowed, `cors_origins` entries are added on top, and `"*"` restores any-origin. Non-browser clients (SDKs, curl, AI CLIs) are untouched: they send no `Origin` and their `Host` is a local literal. Non-loopback binds keep their pre-guard semantics deliberately.

### Added
- **Reranker-class checkpoints are served, not just stored.** bge-reranker-style GGUFs (pooling_type = rank, or the bert architecture) now spawn their llama-server child with `--embeddings --reranking` — `POST /v1/rerank`, the `/v1/reranking` alias, and ollama-style `/api/rerank` return live relevance scores end-to-end. The detection follows upstream semantics exactly: rank-pooling KV or `arch = bert` (exact match — modern-bert is deliberately excluded: its classifier head core-dumps upstream under rank pooling, verified live), no `--pooling` flag is ever sent on this arm (an explicit pooling value neutralizes `--reranking` upstream — 501), and engines whose manifest lacks the flag get a teaching warning with the `blazar engine update` escape instead of a broken boot.
- **Detached daemon auto-boot survives port races.** `ensure_daemon` now watches the spawned child process: a spawn that loses the bind race (another daemon mid-drain, a foreign listener) exits within milliseconds and is retried — bounded at 3 attempts with backoff and a healthy-recheck between attempts — instead of stalling the full 30s budget on a dead process. A respawn happens only after an observed exit, so two daemons can never stack; a live-but-slow child keeps the whole budget. Auto-boot also yields early (~5s instead of 15s) when a systemd unit is up but serving a different port.

Already-live models are skipped, and the list is re-runnable. `idle_ram_warm` (on by default) closes the loop on the other side of the ladder: after the idle timeout evicts a child, a detached single-flight sequential re-read of its weights (plus mmproj, 4 MiB chunks) refreshes the kernel page cache — the RAM tier between VRAM and disk — so a re-spawn faults from memory instead of storage. - **Multi-GiB pulls survive CDN throttle bursts.** A chunk that failed three times in ~10 s of backoff aborted the whole parallel download, so an HF throttling window of a few minutes killed the pull until it was re-run by hand. Chunk retries now span ~100 s (six attempts, backoff capped at 30 s) and honor a seconds-form `Retry-After` response header (clamped to 1-120 s), riding out bursts at the server's own pace. Chunk-accurate resume is unchanged.

- **Engine rows written by a newer binary no longer brick the daemon at startup.** One engines-table row whose `kind` text the running binary does not know (a lane that shipped after it) failed the SQL conversion and errored the entire roster read — serve died at store-open and `Restart=always` crash-looped until the newer binary took over (live incident 2026-09-27: a newer lane's engine row against the 0.13.0 binary, 518 scheduled restarts). Nothing is deleted or rewritten — the rows parse again the moment a binary that knows the kind runs.

The probe — binary, argv, budget — is now one shared spec (`engine::smoke_probe`) used by both doctor's smoke row and the supervisor's post-update verify gate, so the two can never disagree on what healthy means: venv lanes read package metadata through their venv python, whisper answers `--help`, native lanes keep `--version`.

- **The shutdown bank saves and restores every cached slot, not just slot 0.** `bank_save` posted a single `/slots/0?action=save` — with a multi-slot child (`-np N`, or `slots = "auto"` resolving above 1) the conversation lands on a nondeterministic slot, so the bank missed it and the sessions dir stayed empty after shutdown despite `session_bank = true` (live incident: the 2026-09-27 prod sweep SIGTERM'd a warm slots-auto child and the per-model bank dir came back empty; the same daemon minutes later, pinned to one slot, banked fine). The sweep now covers every slot the child actually runs (parsed from its argv, `config.slots` as fallback), bounded at 2 s per slot inside an 8 s total budget so a wide `-np` child cannot hold shutdown hostage; each save keeps its own `_auto-<ctx>-s<id>` checkpoint (slot 0 keeps the legacy name, so old banks and every existing consumer see the same files), slots that report `n_saved: 0` are dropped rather than hoarded, and the whole set honors the existing 512 MiB hoard cap and #20 identity manifests. Restore is symmetric: spawn rebuilds the set from disk and restores each member into its own slot id — a `-np N` child wakes with ALL banked conversations warm — with the same 5 s per-slot bound, warn-continue on a child that has since shrunk its slot count, and identity mismatch skipping the set. The truth indicator is the save/restore response itself (`n_saved`/`n_restored`), not the `/slots` listing, whose `n_prompt_tokens_cache` reads 0 on idle slots even when hundreds of tokens are banked (live-probed on b11202).

- **Best-of-N fan-out degrades are now client-visible and self-healing.** When the saturation guard collapses a fan-out (queued work, no free decode slot) or the 1 MiB body cap skips it, the response now carries `X-Blazar-Best-Of: asked=N used=1 reason=queue|headroom|body-cap` instead of silently answering as if the knob were ignored. A `headroom` degrade on an idle child also records slot pressure, so adaptive slots (`adaptive_slots = true`) reshape the child to more decode slots and later fan-outs run for real.

- **The resolved spec mode now reaches profile compilation — governor parking, per-request `options.spec`, and REPL `--no-draft` were silently ignored.** The supervisor resolves the spec decision through a tier order (per-request > overlay > governor > config) but only ever used the result to pick the draft path and label the instance; `profile::compile` then independently re-derived `overlay.spec ?? config.spec` and built the child argv from that. Every tier below overlay was therefore cosmetic (live incident: the governor parked speculation with `spec_governor_off` + a parked gauge, the reshape respawned the child... with `--spec-type ngram-simple` still on the command line). The bug predates the governor — per-request `options.spec = "off"` and the REPL's `--no-draft` were equally dead — but stayed masked because `spec = "auto"` with no draft pair used to degrade to dense, which is accidentally what "off" wanted; the n-gram auto-fallback un-masked it. `ProfileInput` now carries the resolved `spec_mode` from its only authority (the supervisor; bench/tools mirror the old compile derivation), and compile no longer re-derives. Pinned bidirectionally: a resolved `off` beats an `auto` config (no spec flags emitted — the incident shape) and a resolved `ngram` beats an `off` config (flags engaged).

- **Conversation-affinity and preload-transition tables no longer self-deadlock at capacity.** Both cap-gated inserts (`prefix_affinity` at 512 conversations, `transitions` at 1024 edges) picked their eviction victim with an if-let binding over a `DashMap` iterator — an if-let keeps the iterator's shard read-lock alive through the body, and removing an entry from that same shard needs its write lock, so the very first request that crossed the cap wedged every tokio worker in `ensure_routed_opts` (live incident: a 16-thread bench with ~600 distinct conversations deadlocked the daemon at conversation 512; healthz hung until the process was killed). DashMap locks are runtime shard locks the borrow checker cannot see, which is why the shape compiled at all — std-collection sites with the same look (session registry, semantic cache, heat map, verdict cache) are mutex-guarded std maps where the compiler itself enforces the discipline, and were verified safe. Both sites now bind the victim to an owned value (dropping the iterator guard) before removing; pinned by regression tests that fill each table past its cap on a worker thread and fail if the eviction call does not return.

- **Managed-dir deletion can no longer escape the data root through a symlink.** Every engine/piper/whisper tree-removal path (`engine rm`, retention pruning, orphan sweeps, install rollback) called `remove_dir_all` on a path derived from a directory entry — if the engines dir (or any engine subdir) was a symlink into somewhere else, the sweep deleted the *target's* contents (live incident: a scratch XDG root with a symlinked `engines/` and an empty scratch store booted the daemon, classified all five real engine dirs as orphans, and deleted ~13 GiB of installed engines through the link). All tree removals now go through one guarded primitive in `blazar-core::fs_safety`: the path is canonicalized and must sit inside the data root before `remove_dir_all` runs; a final-component symlink is unlinked as a link (never followed), and anything that resolves outside the anchor is refused with a warning that names both paths. Refusals fail safe per site: `engine rm` errors with a teaching message and keeps the row, retention pruning keeps the row (the engine list stays truthful), orphan/aside sweeps skip the dir, and piper/whisper replace-sites refuse the reinstall outright (replace-don't-merge cannot be honored through a link). Model rows keep their long-standing behavior of deleting user-recorded external dirs on explicit `blazar rm` — that is the user's own path, recorded as such. Pinned by integration tests replaying the incident shape: a symlinked engines root with a populated target survives an orphan sweep with an empty store, a prune-eligible engine behind a link keeps its row and its files, and `remove_engine_row_and_tree` refuses with the teaching error.

### Added

- **GitHub engine downloads ride the parallel byte-range lane.** Release assets — llama.cpp binaries, mistral.rs tarballs, sdcpp, CUDA runtime companions (0.1–1.1 GiB) — downloaded single-stream before: no parallelism, no resume, a killed install restarted from byte zero. Assets with a known size now probe the host with a strict `Range: bytes=0-0` request and, when the CDN answers a clean 206, download through the same chunked machinery model pulls use: 8 connections on 8 MiB chunks, a per-chunk resume ledger (an interrupted install continues where it stopped), full sha256 verification against the release digest, and atomic finalize. The release-API size is enforced after the transfer — a CDN that under-delivers or metadata that lies fails loudly with no partial file surviving. Range-incapable hosts and small assets fall back to the classic single stream, byte-identical to before. Pinned by wire-shape tests: probe-plus-chunks on the wire, 200-only fallback, and the lying-metadata guard.

- **First-class sdcpp tuning knobs: cache mode, flash attention, VAE tiling, RPC offload.** sd-server ships major levers — DiT step-caching accelerators (`--cache-mode` easycache/ucache/dbcache/taylorseer/cache-dit/spectrum), flash attention (`--fa`), tiled VAE decode for small VRAM, and RPC weight offload (`--rpc-servers`, matching the llama.cpp lane's `--rpc` parity) — but they were reachable only through per-model `extra_args`, undiscoverable. Four config fields now expose them globally: `sdcpp_cache_mode` (validated against the six upstream modes), `sdcpp_flash_attention`, `sdcpp_vae_tiling`, and `sdcpp_rpc_servers` (host:port list). Emission rides the probed-manifest gate (an engine lacking a flag degrades with a warning, never a dead child), and user `extra_args` land after them so sd-server's last-one-wins parsing keeps the user's value final. Flash attention ships **on by default** — a seeded A/B on qwen-image (1024², 20 steps) measured 25% faster renders (301s → 224s) at statistically identical output (five-metric stats within ~1%, mean pixel delta 0.46% of range) — while cache mode, VAE tiling, and RPC stay opt-in (cache mode measurably trades detail for speed: 2.2x with −34% gradient energy). Live receipt: the flags verifiably present in the spawned child's argv, and `easycache` + `--fa` cut a seeded render from 319 s to 141 s (>2.2x) including cold weight load.

- **Updates restart a running daemon so the change is live immediately.** A CLI upgrade, engine update/build/use/local registration, or `blazar tune` adoption used to end with "restart the daemon to apply" — the daemon kept serving the old binary, old engine, old tuning until a manual stop. Every such command now restarts the daemon itself when one is provably running, through the narrowest lane available: `systemctl restart` when the unit is active, `launchctl kickstart -k` on macOS, and a privilege-free stop-and-respawn (SIGTERM, wait out the graceful drain — including minutes-long in-flight image generations holding the daemon lock — then relaunch through the same auto-start path) everywhere else. A restart that cannot land is a warning naming the manual remedy, never a failed update; no command grows a daemon-start side effect; re-selecting the same active engine is a no-op. Pinned end to end: the systemd lane is exercised by a hermetic shim (PATH-fronted `systemctl` whose verdicts pick the lane) against a stub healthz server, and the drain-wait by owner-alive/exit unit pins; the stop lane's spawn races the drain by design and now waits for process exit instead of the listener alone.

- **Adaptive reshape drains gracefully instead of starving under sustained load.** The reshape used to wait for a global idle that continuous traffic never produces (live receipt: 20260924-all-engines, flat 39 t/s at C=8 for a whole campaign — the drain skipped every tick). Now a busy drain tick marks the model `reshaping` (the admission gate parks new requests on that mark and feeds the pressure gauge), and the first idle tick evicts, respawns at the adopted shape, clears the mark, and publishes `SlotsReshaped` — the gateway's wake task releases every parked waiter on that event (and on engine updates), so queued demand lands on the fresh slots immediately. A failed evict keeps the queue entry for retry; a failed respawn holds the mark one more tick instead of thrashing. Pinned by the drain-holds-while-busy unit test, which runs the real respawn path (store row, GGUF metadata, profile validation, FakeEngine child) end to end.

- **`serve` self-heals a zero-active engine store.** An engine update interrupted before its activation step used to leave every installed engine behind one stale `active` flag — installed but unusable until a manual `engine use`. On boot, when no row holds the active flag, serve activates the best candidate (llama.cpp preferred, then mistral.rs/sglang, newest install wins; lazy lanes — whisper, sdcpp — never claim the slot) and says so on stdout.

- **Engine rows store data-dir-relative server paths.** Manifests recorded the absolute binary path at install time, which made rows non-relocatable (a moved/copied data dir needed a re-root workaround on every load) and baked machine-specific paths into the db. Rows now persist `engines/<tag>/...` relative to the data dir (the out-of-tree `local` lane keeps its user-given path), anchored back to an absolute live path at every decode — spawns, probes, and the orphan sweep see the same absolute paths as before, and the boot pass migrates legacy absolute rows in place.

- **`validate.py --smoke`: a fast pre-commit subset of the E2E harness.** The full 227-check run is the release receipt (~10-15 min with model loads); day-to-day commits only need the signal that the common breakage classes survived — binary boots, daemon spawns and serves chat, config surface, CLI surface, golden drift. `--smoke` runs exactly those six phases (~2-4 min, one 0.5B load; latest receipt: 117 checks, 0 failed) and deliberately skips the coverage-ledger phases, which redden when the rows they audit never ran. An explicit `--phase=` still wins over the preset.

- **The daemon owns a durable log file under every launcher.** `blazar serve` now tees its tracing output to `run/daemon.log` directly (rotated at 10 MiB to `daemon.log.1`), not only when auto-started by the CLI wrapper — under systemd the journald stream was the sole sink and a journal rotation stranded it, leaving zero daemon logs for post-mortems. Non-serve commands keep stderr-only logging.

- **`blazar doctor` names ghost engine rows.** A db row whose engine dir was deleted underneath it (manual removal, disk cleanup) previously passed every doctor check while spawn/verify silently couldn't see the binary. Doctor now lists each ghost row with its anchored path and the heal command (`blazar engine update --kind <kind>`; whisper rows note the legacy tree still serves transcription; the `local` lane teaches the `BLAZAR_ENGINE_PATH` remedy).

- **engine-check.json writes are atomic.** The currency marker is now written via tmp+rename; a plain write racing a reader (or a second daemon generation during restart) once left two concatenated JSON objects in the file.

- **Children can serve over Unix-domain sockets (`child_transport = "unix"`).** Every llama-lane child spawns on a deterministic `run/<name>.sock` in the daemon's run directory instead of an ephemeral loopback port, and every gateway→child hop (proxy hot path, metrics scrape, warmup peg, session-bank save/restore, tokenization and embedding probes, images and batch lanes) dials the socket through a bounded per-path client pool. Sockets are swept for stale files at boot and unlinked on eviction; a path that would blow the OS `sun_path` budget fails fast with a teaching error naming the component. `tcp` stays the default and is byte-identical to before; `unix` is rejected at config validation on non-unix platforms.

- **Anthropic image blocks reach the engine.** `translate_message` used to collapse every `image` block into a `[image: …, N bytes]` text marker — the vision model never saw the picture. Base64 sources now re-serialize as data-URL `image_url` parts (format-sniffed: png/jpeg/gif/webp), URL sources pass verbatim, tool-result images become `role:"tool"` content parts (upstream accepts image parts there), and a malformed source is a 400 `invalid_request_error` instead of a silent marker.

- **Vision routing covers video and tool-image parts.** `body_needs_vision` now recognizes `input_video`/`video_url` parts (llama.cpp ≥ b11147 surface) and media nested inside responses-lane `function_call_output.output[]` items, so those requests land on projector-bearing replicas instead of failing child-side.

- **RPC worker handshake failures teach the fix.** A child whose `--rpc` worker answers TCP but runs a mismatched ggml build (version-mismatch abort, handshake failure, connect abort in the dying log tail) surfaces an `EngineCrashed` payload that names the engine build, the stale worker address(es), and the remedy (restart workers from the same-era build or drop them from `rpc_servers`) — classified only when the spawn's argv actually dialed `--rpc`.

- **Whisper models and piper voices are searchable before pulling.** `blazar whisper --search [substr]` lists every ggml size the upstream `ggerganov/whisper.cpp` repo ships (tiny..large-v3-turbo, `.en` variants, q5/q8 builds — 33 models today) with DISK bytes and a `pulled` marker on what is local; `blazar tts --search <substr>` does the same for the `rhasspy/piper-voices` catalog — search by language (`en`), locale (`en_GB`), or name (`amy`), top 40 rows with a showing-N-of-M note. Both ride the Hub tree API with cursor pagination (the siblings listing the old code path used truncates this repo at ~3300 files, hiding most voices), a language-prefix query narrows the walk to that language subtree, and any other substring walks all languages in parallel. Every row resolves through the same id grammar `--pull` accepts, so nothing listed can dead-end.

- **Multimodal GGUFs boot on the mistral.rs lane instead of refusing at config time.** A GGUF that carries a projector (mmproj) but not its original `config.json` — the standard shape of lmstudio-community repacks — made a raw mistral.rs child abort at startup with `multimodal GGUF requires its original config.json ... pass --tok-model-id`, even though the base model exists on the Hub under a name derivable from the file's own metadata. The launcher now derives that id (`general.basename` `Org_Model` + `general.size_label` → `Org/Model-<size>`, exactly how the packagers name the source repo) and passes `--tok-model-id` on the spawn line whenever the installed engine advertises the flag — live-proven on Qwen3.5-9B: config refusal gone, server healthy, chat 200. GGUFs whose metadata can't name a Hub repo (single-segment basenames) keep the engine's teaching error instead of a guessed download. The gateway's architecture routing is unchanged — GGUFs still prefer the llama.cpp lane; this unblocks the mistral.rs lane when it is the one serving (no llama.cpp engine installed, or an explicit engine override).

### Changed

### Fixed

- **Every pull lane now re-uses byte-exact files before downloading.** Content-first reuse existed only on the diffusion-component path; a row-less re-pull (store row deleted, file intact on disk) rode the main download path and re-downloaded a byte-exact 4.3 GiB DiT through `.part` — only `.part` resume existed there. The bare-leaf → collision-resolved dest → huggingface-hub-cache decision is now one shared helper consulted by every download site (gguf shards, mmproj sidecars, safetensors shards, components): a hit records the reused path on the row, advances the progress bar, and sweeps the stale `dest.part`/`.part.progress` orphans from interrupted attempts. Multi-shard pulls adopt a bare leaf only when the set is a single file, so shard-set derivation from the recorded path never strands siblings at a disambiguated name. Live-verified: the exact incident scenario now rebuilds the row and full component set in 12 s with zero network transfer (a wiremock pin additionally proves exactly one blob request across both pulls).
- **Session-bank save/restore now report the token truth, not just HTTP 200.** A bank restore could log "restored banked session" while the checkpoint actually injected zero tokens (upstream has a restored-then-empty re-prefill bug class). Both slot actions now parse the engine's own counts from the response — restore logs the injected token total and warns "continuing cold" on a zero-token 200; save warns when it banks an empty slot instead of a cached prefix (happy path stays a debug line). The counts are live-verified semantics: a 31-token save/restore cycle on this engine served the next same-prefix request with `cache_n = 23, prompt_n = 1` (96% prefill skip). The `cache_reuse` knob doc no longer claims "cross-slot prefix sharing" — `--cache-reuse N` reuses KV chunks within one child's own slot cache, per-process, never cross-replica.
- **The engine help census no longer drops underscore flags.** The shared `--help` parser filtered flag lines through a dash-era charset, so sd.cpp's five underscore flags (`--llm_vision`, `--clip_vision`, `--qwen2vl_vision`, `--clip_g`, `--clip_l`) never reached the engine manifest — and the strict probed-flags argv gate then refused `--llm_vision` at spawn, silently degrading `/v1/images/edits` to a confusing upstream "generate_image returned no results". The charset now admits `_`, the five flags probe cleanly (152 → 157), and existing installs recover by re-running `blazar engine install --kind sdcpp` (re-probe in place).
- **Memoryless device census rows never reach the GPU pool.** sd.cpp's `--list-devices` prints accelerators without memory numbers (all `total_mib = 0`); copied verbatim into the hardware census they made the GPU picker tie-break on zero and hand a Vulkan device name (or worse, the host `CPU` row) to a CUDA llama-server, which crashed at spawn (`invalid device: CPU`). Census rows without memory totals are now treated as "not a capacity census" — the picker falls back to nvidia-smi when the whole pool is memoryless, and the sd.cpp device parser drops the host CPU row outright (it is not an accelerator). The sdcpp offload ladder also gets real VRAM numbers back for its placement decisions.
- **Component re-pull re-uses byte-exact files even when the store name differs.** The reuse check ran on the store's collision-safe (repo-prefixed) destination name, so a hand-placed byte-exact file under its bare leaf name missed the check and triggered a full multi-GiB re-download next to its own copy — on a nearly-full disk that aborted the whole pull. Reuse is now checked against both the bare leaf and the resolved destination (size gate, then sha256 when known), pinning the truth table.
- **A diffusion-family row without its component set is a repair, not "already present".** The re-pull gate treated a never-attached set (`NULL` components) as fine and the repair path only fired when at least one component path existed, so `blazar pull` on a family-known row reported present without attaching the set. Any row whose repo matches a known diffusion family now requires every required component file to exist; a fixed-binary re-pull attaches the missing set and leaves the DiT untouched.
- **A 0-KV component GGUF on disk is intact, not corrupt.** The re-pull integrity gate required the GGUF metadata parse to succeed, but diffusion DiT files never carry `general.architecture` — sound on-disk sets were pruned as failed-integrity and re-downloaded in full. The gate now walks the container structurally: the exact "missing general.architecture" parse error means the header, KV section, and tensor table all parsed cleanly, so the file is byte-structurally fine for the sdcpp lane.
- **`doctor` port check now verifies daemon identity, not just liveness.** A bound port answering `/healthz` used to be reported as "blazar daemon already answering" — during the rename window a pre-rename pallama daemon (same default port 11435) earned a false ok. The daemon's `/api/version` now advertises `name: blazar`; doctor reports ok only for a named blazar answer, warns with the observed version for a pre-rename/foreign daemon, and keeps the occupied-port hint otherwise.

- **Parallel-lane pulls now resume at byte granularity instead of restarting from zero.** The parallel download lane (default ≥8 connections for files ≥32 MiB) split files into 8–128 MiB chunks but persisted its `.part.progress` resume ledger only when a whole chunk finished — with chunks spread across connections, none finished until the file was nearly complete, so any interrupt (Ctrl-C, network drop, daemon kill) left a full-length sparse `.part` with no ledger and the next pull hit the orphan heuristic and re-fetched every byte. The sidecar is now v2 with an aria2-style per-chunk ledger: it is seeded the moment the lane engages, workers count only bytes that survived a positional write (refunding counters when a retried attempt rewinds), and the coordinator snapshots every pending chunk's verified prefix on a 1s cadence plus immediately on each chunk completion. ### Added
- **`blazar pull <target> --verify`: re-hash a pulled model against its recorded sha256.** Verify-only mode — no network, no pull lock: streams the file through sha256 on the blocking pool and exits non-zero on a mismatch, printing the expected and actual digests plus the file path. Registry pulls (content digest), HF GGUF pulls (LFS digest) and `model:tag` aliases all resolve; safetensors directory rows are refused loudly (their stored hash is a revision identity, not a content digest) and rows without any digest are reported as unverifiable instead of failing. The `--verify` flow ran live against the interrupted-pull test bed: the completed qwen3:0.6b (498 MiB) verified exit 0 with the digest matching the registry manifest byte-for-byte, a single flipped byte flipped the verdict to exit 1, and restoring it restored exit 0.
- **Ledger persistence is now crash-ordered.** `store_sidecar` fsyncs the `.part` data before writing the ledger, fsyncs the ledger tmp file, renames atomically, and fsyncs the parent directory — a power loss can no longer leave a sidecar claiming bytes the `.part` does not actually hold. The fsync steps degrade with a warning (never abort the download) on filesystems that refuse sync; a missing `.part` still gets its ledger written, which a regression test pins.
- **`blazar search --quant <q>`: filter search results by quantization on each repo's real file set.** The Hub exposes no quant facet, so the filter runs client-side against the same quant set the QUANTS column renders (per-file GGUF tokens, repo-id bit-width markers for safetensors/MLX lanes — filter and table can never disagree). `--quant q4` matches the whole Q4 family (`q4_0`, `q4_k_m`, `q4_k_xl`, `iq4_xs`, …), `--quant Q4_K_M` that exact quant, comma-lists OR (`q4,q5`), and matching is case-insensitive; an `iq4` filter stays i-quant-only. A bare query token that is itself a quant (`blazar search qwen image 2.1 gguf q4`) is lifted out of the Hub full-text query into the filter automatically — such tokens are dead weight server-side — with a stderr notice (stdout stays clean for `--json` pipes); `--format` composes independently. Quant token extraction also widened, verified against a 4,346-file live Hub scan: double-extension layouts (`Q4_K_M.GGUF.gguf`, ~5% of scanned files) and quant-in-folder layouts (`Q4_K_M/model.gguf`) now yield tokens in both the search table and the `pull <repo>:quant` path, which shares the grammar.

### Fixed

### Fixed


- **Dead `--rpc` endpoint no longer crash-loops the child**: upstream
  llama-server connects RPC backends eagerly at argv-parse and SIGABRTs
  when one is down (ggml-rpc.cpp), so a `rpc_servers` entry pointing at
  a stopped worker turned every spawn into a crash-loop of 502s. Every
  `--rpc` endpoint in the final child argv (global knob, model overlay
  and `extra_args` occurrences alike) is now TCP-probed in parallel
  (2s budget) before the process exists: a dead one refuses the spawn
  with a teaching 500 naming the endpoint, with no child process, no
  engine rollback and no circuit-breaker trip — the engine binary is
  healthy, the worker is not.
- **Bank restore defers while the triggering request runs**: the
  detached slot-restore still queued the request that caused the
  spawn ~1s behind cache priming (the pending request was invisible
  to busy-polls). `ensure_routed` now brackets itself with a pending
  counter and the restore posts only at idle (100ms poll, 30s bound,
  bank preserved for the next spawn). Racing request: 5.44s vs the
  5.3s no-bank floor.
- **Session-bank restore leaves the spawn critical path**: the ~1s
  slot-0 restore POST runs detached behind an fs-only identity
  preflight, so Ready publishes at engine-health time (cold 9B
  5.37s vs ~6.4s) and non-racing first requests pay nothing;
  continuation chats still get the banked KV.
- **Evict teardown no longer pins a std lock across awaits**: the
  evicting mark is a `tokio::sync::Mutex` with an explicit async
  release (every exit path clears it; a leaked mark starved every
  future spawn of that name — the `/api/evict`-timeout wedge class
  observed once live). Concurrent `stop`+`run` churn on a 9B is
  clean 6/6 (was 3/6 with spawn failures).
- **mlock auto-policy charges resident siblings**: the 40%-of-RAM
  gate now counts other live instances' weights, so a churn
  replacement racing its dying predecessor's pinned pages degrades
  to plain mmap instead of double-pinning (2 × 5.4 GiB mlock on
  13.6 GiB RAM live-repro'd as spawn failures).
- **Bench warm cells assert GPU idle**: `gpu_busy_mib` recorded in
  cells.jsonl; contaminated runs self-label instead of silently
  halving both sides' decode numbers.
- **Sub-weights `--cache-ram` budget no longer CPU-splits the model**:
  the unified-KV budget floor now derives from rule 2b's own
  constraint at the ctx floor (weights + f16 KV + 64 MiB, over the
  0.85 compute share) and engages rule 2b at the raw budget — floored
  spawns stop hard-warning by construction and autofit ctx outcomes
  survive.
- **Bench cross-runtime prefill parity**: the ollama lane (no tokenize
  route) sized prompts by char estimate — 371 real tokens vs blazar's
  527 at the same target. Lanes now converge on the engine's own
  `prompt_eval_count`; re-measured same-token counts put blazar at or
  above ollama on every metric (prefill 1346 vs 1337 t/s, decode 41.1
  vs 40.5, ttft 123 vs 131 ms, qwen3.5-9b warm) — the reported 29%
  prefill gap was a measurement artifact.

- **Draft-decline keeps the gpu-layers pin**: the wave-5 unpin
  (draft pairs leave `--gpu-layers` to the engine fitter) now only
  applies when the draft will actually attach; a capacity-declined
  draft (running dense) keeps the pinned fast path instead of
  inheriting the fitter's conservative split.
- **Sub-weights cache-ram budget under unified KV floored at the
  weights** (3.3x decode fix): on a 13.6 GiB RAM / 8 GiB VRAM box the
  30% clamp (4102 MiB) sat below qwen3.5-9b's weights (5417 MiB) while
  `--kv-unified` was on, so the engine's live fitter honored the
  unsatisfiable sysmem budget and CPU-split the layers — 15.6 vs 39.9
  t/s, silently. The budget is now floored at weights + KV floor +
  64 MiB with a loud warning (measured numbers included); a floor over
  60% of RAM keeps the clamp and teaches `kv_unified = false` / smaller
  quant instead. Default-config 9B decode is 40.9 t/s (was 12.4;
  ollama 40.5 same-settings, direct ceiling 41.2).
- **Spawns plan against live census VRAM, not the boot snapshot**:
  single-GPU boxes fell back to the daemon-boot `Hardware` when no
  card pick applied, so a daemon started while a foreign context
  (e.g. the user's ollama model) held VRAM would forever CPU-split
  spawns and decline speculative drafts against stale free-VRAM
  readings (live-repro'd: 7.8 GiB free, planner saw 3.2 GiB). The
  profile now uses scoped-pick > fresh census > boot snapshot, and
  evict invalidates the census cache so our own teardowns are
  re-measured. Measured effect on qwen3-8b + draft pair: 28 t/s
  dense CPU-split → 45.8 t/s spec-accelerated full-GPU.
- **`run` parses its flags instead of swallowing them into the
  prompt**: `trailing_var_arg` made `blazar run m 'Say ok'
  --max-tokens 5 --verbose` send the flag TEXT to the model and
  never parse either flag (live-repro'd: every completion echoed
  "--max-tokens 5"; `--verbose` stats silently absent from the
  wave-6 TTFT notes). Flags now parse normally before the prompt; a
  leading `-` word needs quoting or `--`.
- **Circuit breaker counts crash restarts, not churn**:
  `record_restart` fired on every successful spawn, so a user
  stop→run churn ×4 inside the 60 s window opened the breaker on the
  5th and 503'd until `blazar ps --reset` (live-repro'd). Restarts
  now count only when the spawn consumes an unclean-death mark set by
  the child reaper (non-zero exit); clean teardowns (stop / idle /
  capacity) reset the mark — churn is a cold start, not a crash loop.
- **Draft KV charged in the co-residency planner**: the pressure and
  admission math counted only the dense model's KV
  (`kv_est_bytes`), so a speculative pair's draft KV (device-side,
  often LARGER than its weights — e.g. 2.2 GiB vs 0.35 GiB on the
  eagle3 8B pair) was invisible to card-capacity decisions. The
  profile now adds the draft's f16 KV at the resolved ctx (unified:
  on top of the floor; classic: on top of the quantized dense KV);
  an unreadable draft header degrades to dense-only with a daemon
  warning rather than blocking the spawn.
- **Speculative drafts no longer pin `--gpu-layers 999`**: the draft's
  weights + KV allocate DEVICE-side beyond any planner charge, and a
  hard pin disables the engine's live fitter (`n_gpu_layers already
  set by user to 999, abort`) — shared-GPU spec pairs could
  cudaMalloc-OOM. Spec pairs now leave `--gpu-layers` to the fitter
  (`auto`), in both unified-KV and classic accounting, with a profile
  warning saying so. Dense models keep the pinned fast path.

  a spawn is admitted while the SUM of resident instance weights plus
  the incoming model stays within total VRAM, replacing the old
  `floor(VRAM / largest_model)` heuristic that locked heterogeneous
  pairs out (0.5B + 9B co-reside on an 8 GiB card; a second 9B still
  evicts). Explicit `max_loaded_models > 0` keeps pure-count semantics,
  CPU-only boxes stay pinned to one instance, and the fresh free-VRAM
  probe (spawn guard) still owns refuse-vs-warn at load time.
  `Supervisor::capacity_for` replaced by `instance_cap` /
  `bytes_admission_active` / `resident_bytes` / `vram_budget_bytes`.

## [0.5.0] — 2026-09-10

Behavior-changing release: spawn-time concurrency, honest capacity math.

### Added (2026-09-12 demand-driven slot reshape — LC4 generalized, live-proven)

- **Demand decay**: after 30 quiet reaper ticks (5 min at zero in-flight),
  an adopted slot shape decays back to the natural capacity shape via the
  same idle-drain respawn (per-stream latency recovers: np8 ITL ~60 ms vs
  np4 ~37 ms). Asymmetric hysteresis by design — scale-up needs 60 s of
  proven pressure, scale-down needs 5 min of quiet; saturation re-raises
  in 60 s if demand returns.
- **Adaptive slots now react to real demand**: the trigger is a gauge over
  requests parked in the admission gate (`AllSlotsBusy` queue waits — the
  same-model concurrency park), not the unobservable `in_flight > slots`
  comparison; saturation across 6 reaper ticks (60 s) adopts `-np +1`
  (cap raised 4 → 8 on the measured np8 scaling win: conc8 sys +19%,
  queue-TTFT 5.4× better), and the reshape **respawns the instance at the
  first idle drain** (KV bank carries conversations) instead of waiting
  for the next natural spawn. Explicit `slots` overlays, replicas, and
  `deterministic` models are excluded; a spawn failure rolls the adoption
  back and clears the reshape queue.
- **`slot_cap()` live resolution** replaces the gateway's hardcoded
  admission cap of 4 (which silently defeated any adopted np5-8 shape):
  adopted value → live child argv `-np` → explicit config → default,
  with replica/vision key canonicalization.
- Live proof: 12-stream sustained load on a 4-slot instance → gauge
  fills (37-74 s parks) → adopt 5 → idle drain → respawn at `-np 5`,
  greedy outputs bit-identical before/after (zero quality loss).
- Four falsified designs on the way (in-flight comparison unreachable
  through admission control; event counter drained per tick; gauge
  bracketed on the multi-model-only `AllSlotsBusy` raise) — probes and
  artifacts in `/tmp/opencode/flagprobe/`.

### Added (2026-09-12 scaling flag-space study — measured, no default changes)
- **Flag-space study (b10903, qwen3.5-9b, RTX 4070)**: probed `-ub 2048/4096`, `--kv-unified-per-slot`, `-tb`/`-Crb`, `--poll 100`/`--threads-http`, and slot-shape scaling (`np8×32768` vs `np4×65536`) across short-prompt, long-prefill (2k/8k), and 8-stream sustained regimes. Greedy parity 5/5 and 2/2 on every config — all levers are scheduling-only, zero quality impact. Verdicts: `-ub` above the 512 default is a measured REGRESSION on long prefill (2111 → 1728 t/s at 8k, +360 MiB) — default stays; slot scaling is the concurrency lever (np8: system +19%, TTFT p99 5.4x better at 8 streams, −246 MiB; np4 keeps per-stream ITL 37 vs 60 ms) and the existing capacity-probed auto-slot rule already picks the balanced shape; `--poll 100` trims conc TTFT p99 ~11% at the cost of CPU busy-spin — documented as a high-concurrency recipe (`model_overrides.<model>.extra_args`), not a default.

### Added
- **Slots auto-fit** (throughput-first parity with ollama's VRAM-tier ctx
  default): when `slots = auto` resolves to ONE slot and the ctx came from
  `default_ctx` (not pinned by model overlay, bench tuning, or a per-request
  `num_ctx`), the same total-ctx capacity budget is re-spent as parallel
  shallow slots — e.g. 1x16384 becomes 4x4096 (floor 4096, ollama's own
  default ctx). Identical VRAM/KV budget under both the unified per-token
  guard and classic KV math (N x ctx/N == 1 x ctx), so boot risk is
  unchanged while concurrent streams batch instead of queueing (measured
  37 -> 98 t/s system at 4 streams on the tight lane). Prompts longer than
  the per-slot ctx take the existing teaching 400 + `num_ctx` restart-once
  path. Surfaces a `slots_ctx_auto_fit` event, `Profile.ctx_autofit`, and a
  loud spawn warning; any ctx pin disables it.
- `deterministic` config knob (global + per-model override, default false):
  pins slots = 1 in both engine lanes so greedy decoding reproduces
  token-for-token — multi-slot batches perturb logits in near-tie
  positions (measured: auto-slots np=4 flipped 14/20 greedy probes vs
  the same child at slots = 1). An explicit `slots > 1` under the pin
